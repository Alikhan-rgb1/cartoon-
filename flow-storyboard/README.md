# Flow Storyboard Auto

Расширение для Chromium-браузера: берёт сценарий по кадрам и фото персонажей, сам генерирует кадры в Google Flow и по умолчанию оставляет их во Flow (по галочке «скачивать каждый кадр» ещё и скачивает в `Загрузки/Cartoon/frame_001.png…`).

## Установка (для проверки)
1. Откройте `chrome://extensions`, включите «Режим разработчика».
2. «Загрузить распакованное расширение» → папка `flow-storyboard`.
3. Откройте проект в Flow (`flow.google.com/project/…`) и войдите в аккаунт.
4. Нажмите на значок расширения: откроется боковая панель.

## Один клик: сценарий → промпты → Flow
В блоке «0» вставьте согласованный сценарий по кадрам (без промптов) и бесплатный ключ Gemini API (aistudio.google.com/apikey), нажмите **«Сделать раскадровку»**. Число кадров считается само.
Промпты пишет `promptgen.js` через Gemini API в два этапа: сначала «библия» (места действия и одежда персонажей в каждом месте), затем кадры пачками по 6 параллельно (эмоции, действие, свет, камера, атмосфера, планы). Итоговый текст собирается шаблоном в коде — в той же структуре, что у Gem (строки «Use the attached reference photos for the father…», «Master Location…», одежда, … , стиль), поэтому формат всегда одинаковый.
**Статус:** модуль проверен только офлайн (с подставным ответом API): структура промпта, роли, одежда, поиск персонажей. С настоящим ключом и в Chrome ещё не запускался. Название модели по умолчанию `gemini-flash-latest` (если не найдётся — пробуется `gemini-2.5-flash`, имя можно вписать в «Настройки промптов»).
Бесплатный тариф: лимиты по запросам в минуту/день у разных моделей разные, сверять в AI Studio; на бесплатном тарифе Google может использовать запросы для улучшения своих продуктов (учитывать при работе с историями клиентов).
**Источник промптов** (Настройки промптов): «Авто» — сначала Gemini API, а если суточный лимит исчерпан, Gemini занят или нет ключа — автоматически ваш Gem на сайте Gemini (`gemini.js`: отправляет сценарий, отвечает числом кадров, пишет «дальше» по 5 кадров, пока не наберёт нужное число). У Gem нет суточного лимита API, но он медленнее, и вкладка Gemini открывается на виду (у скрытой Gemini не обновляет ответ). «Только API» / «Только Gem» — принудительно. «Без ИИ» — мгновенный шаблон.
Запросов к API: до 12 кадров — один; дальше — один на «основу» и по одному на каждые 12 кадров. Модель с исчерпанной квотой («Quota exceeded … retry in 4h…») пропускается без запросов до сброса, берётся следующая.
**Свой Gem (рекомендуется для запасного пути):** инструкция в `gem-instructions.md`. Он за один ответ выдаёт JSON (места, одежда, внешность героев без фото, поля кадров); расширение отправляет ему одно сообщение, забирает JSON и собирает промпты тем же кодом, что и для API (`promptKit` в `promptgen.js`). Длинные истории отправляются пачками по 12 кадров («Next frames…»). Если по ссылке открывается старый Gem (отвечает вопросом), расширение общается с ним по-старому (через «дальше»).
Проверено офлайн (подставной API): число запросов, переключение моделей при исчерпании квоты, ошибка при исчерпании всех. Запасной путь через Gem как цельная цепочка в Chrome ещё не запускался.

## Использование
Сценарий в формате `Кадр 1: …`, персонажи с подписью (папа, мама…), которая встречается в тексте кадра, число кадров, «Создать». При исчерпании лимита остановится и продолжит с того же кадра.

## Статус
Проверено вручную на живом Flow (окт. 2026): ввод промпта, прикрепление референса, программная загрузка фото персонажа, получение результата (`img.image`), Flow учитывает референс.
**Расширение целиком в Chrome ещё не запускалось.** Не проверено: клик через `chrome.debugger`, текст сообщения о лимите (`limitMessage`), поведение при проверке на бота (reCAPTCHA).

## Важные особенности Flow
- Персонажи: первый раз фото **вставляется в поле промпта** (событие paste, как Ctrl+V; проверено на живом Flow — прикрепляется ровно присланный файл). Дальше (имя запоминается по проекту) расширение выбирает уже загруженный файл из окна «+» по точному имени, а картинку в запросе сверяет с вашим фото (отпечаток 8×8). Если не совпало — очищает запрос и вставляет фото заново. Выбор из библиотеки без проверки раньше путал персонажей (в кадрах 2–3 вместо папы цеплялась мама). **Эта схема (выбор из библиотеки + проверка) в живом Flow ещё не запускалась.**
- После генерации Flow очищает запрос вместе с ингредиентами, поэтому персонажей нужно добавлять в каждый кадр.
- Если после кадра пропало поле промпта, в ошибке пишется адрес страницы и названия полей — по этой строке можно понять, где оказался Flow.
- Кнопка «Начать генерацию» принимает только настоящий клик, программный игнорируется → клик отправляет `background.js` через `chrome.debugger` (Chrome покажет плашку об отладке).
- Строки в окне «+» — `flow-add-menu-popover-content button.asset-item`; плитки `flow-grid-tile-container` относятся к основной сетке проекта, клик по ним открывает редактор.
- Селекторы собраны в одном блоке `SEL` в `content.js`: при обновлении Flow править там.
